# lab6 · 能力目标与接口约定（文件系统：块缓存与 WAL 日志）

> 本实验实现持久化存储管理：
  设计并实现块缓存层（Buffer Cache）、预写日志（WAL）与文件/目录（inode）管理机制。
  同时完成系统架构的重大升级——将用户程序（exec）的加载来源由内核内嵌二进制映像全面切换为自主实现的文件系统。

## 1. 能力目标（由你设计并实现）

1. 块缓存层：实现块替换策略 `LAB6_REPLACE_POLICY`（LRU / FIFO / CLOCK / LFU 四选一），
   管理 `LAB6_BUF_SLOTS` 个缓存槽位；确保脏块在被淘汰释放前必须先写回磁盘。
2. WAL 预写日志：支持 `LAB6_LOG_BLOCKS` 个日志块；严格遵循"先写日志意图、写入提交标记（Commit Record）、再写回实际数据块（Install）"的原子事务流程；
   通过检查提交标记状态准确处理各种突发断电崩溃点。
3. inode 与文件目录操作：实现 ialloc/dirlookup/dirlink 等核心函数以及
   sys_open/read/write/link/unlink 系统调用。
4. 程序加载机制全面升级：将 exec 的加载来源由内嵌程序表切换为自主构建的文件系统
   ——系统执行 `make qemu` 启动后依然直接进入 sh 交互环境，但 sh 及其子程序均由磁盘文件镜像中动态读取。

## 2. 接口约定与核心规范

1. **磁盘物理布局规范**：使用 mkfs 工具（预置环境辅助工具，已参数化）制作磁盘镜像；日志块数量
   固定为 `LAB6_LOG_BLOCKS`，由构建配置通过宏注入（`-DLAB6_LOG_BLOCKS=…`，不与 param.h 中的 LOGBLOCKS 产生冲突；
   详见 gifts/Makefile.upgrade）。
2. **受控断电模拟规范**：使用 `support/crash.c` 中的 `crash_at(stage)` 接口——
   在日志提交过程的关键阶段模拟系统突发断电崩溃（代码已完整提供，请勿修改；学生需在设计笔记中制定崩溃状态表，
   将实际日志提交阶段映射为具体的 stage 编号）。
3. **功能回归测试规范**：lab2 的 inject_uart shell 交互式压力测试必须依然全部通过
   （确保底层系统调用与终端驱动在引入文件系统后依然稳定正常）。

## 3. 设计决策（设计笔记必须明确回答；现场验收重点考查）

- 缓存块替换策略的数据结构设计与时间复杂度；脏块与干净块在淘汰路径上的处理差异。
- **日志保护范围界定**（数据块与元数据块的边界划分——本实验设计的核心关注点）；为什么读到过时数据通常不属于日志恢复机制所能解决的范围。
- 崩溃恢复状态表：断电时刻枚举与日志恢复判定树的化简推导。
- begin_op / end_op 事务边界与文件并发读写的同步互斥控制；锁获取顺序与死锁规避策略。

## 4. 预置支撑代码（gifts/，保持只读）

- `mkfs/mkfs.c`（磁盘镜像制作工具，作为宿主机环境构建工具；其生成的磁盘布局即为文件系统底层规范）；
- `kernel/virtio_disk.c`（VirtIO 磁盘驱动程序；设备硬件协议作为外设支撑事实，不列入学生编写考核范围）；
- `kernel/virtio-deps.md`（**驱动依赖接口定义**：定义了 struct buf 最小字段集合、调用上下文假设——自主编写的缓存层仅需满足此接口依赖）；
- `support/tests/{fsstress.c,crashmap.md}`：并发读写与硬链接一致性测试程序及受控崩溃测试表模板。

## 5. 里程碑自检

1. 并发文件读写测试无数据交叉损坏与文件系统结构破坏（通过并发压力测试）；
2. 在 crash_at 设置的各个断电阶段触发模拟崩溃后，重启系统进行恢复：文件系统状态必须呈现原子性（要么完整提交、要么完全回滚），崩溃表逐项验证通过；
3. 脏缓存块在被换出淘汰前必然先同步刷盘，具备明确的可观测记录（通过日志或计数验证）；
4. sh 程序成功从磁盘镜像中解析并加载运行（完成 exec 加载源的全面替换）；
5. **功能回归**：重新运行 lab2 的 shell 压力交互测试，测试全部正常通过。
