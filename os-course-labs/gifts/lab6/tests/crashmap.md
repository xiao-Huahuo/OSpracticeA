# 官方测试 · lab6-test2：受控断电恢复（崩溃状态表模板）

> 测试驱动 = 预置支撑模块 `support/crash.c` 中的 `crash_at(stage)`；本文件提供
> **崩溃状态表模板**：学生将自主实现的 WAL 日志各个阶段映射到对应的 stage 编号并逐项验证。
> 现场验收将参考本表随机选取 2 处断点进行重放验证。

| stage | 模拟断电时刻（语义） | 系统重启后的正确行为 | 判定标准 |
|---|---|---|---|
| 0 | 事务正式开启前 | 目录与文件保持原样 | cat f0 输出内容与断电前完全一致 |
| 1 | 日志意图块写入过程中（部分日志块已落盘） | **事务放弃回滚**：新文件不存在或保持旧版 | 文件内容 = 旧版内容 |
| 2 | 日志意图块全部落盘、提交标记（Commit Record）尚未写入 | **事务放弃回滚**：同上 | 文件内容 = 旧版内容 |
| 3 | 提交标记已写入、数据块写回（Install）尚未开始 | **日志重放恢复**：新版本数据完整可见 | 文件内容 = 新版内容 |
| 4 | 数据块写回进行到一半 | **日志重放续推**：新版本数据完整可见 | 文件内容 = 新版内容 |
| 5 | 数据块全部写回完成、日志头尚未清空复位 | **重放具有幂等性**：再次重启系统状态保持不变 | 连续两次重启验证内容一致 |

## 操作步骤（针对每一测试断点）

1. 执行 `make fsimg && make qemu`（挂载文件系统镜像 fs.img），在 sh 中运行写文件测试程序
   在**崩溃断点触发前**完成 open/write/close 操作；
2. 在内核日志提交路径的对应位置通过 `crash_at(N)` 触发模拟断电崩溃；
3. 重启 QEMU，在 sh 中使用 `cat` 命令校验文件内容，对照上表"判定标准"记录 PASS / FAIL；
4. 针对 stage 5 额外执行第二次系统重启，验证日志重放过程的幂等性。
