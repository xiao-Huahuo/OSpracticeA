# 预置支撑代码 · virtio_disk 驱动依赖接口定义（缓存层接口约定）

> VirtIO 设备硬件协议本身**不属于本课程核心教学目标**；驱动程序作为既定的底层支撑。学生只需
> 确保自主设计的缓存层（buf/bio）满足以下接口规范与调用约定即可无缝衔接。

## 1. 驱动暴露的核心函数

```c
void virtio_disk_init(void);          // 在 main 函数的文件系统初始化阶段调用一次
void virtio_disk_rw(struct buf *b, int write);  // write=1 表示写盘，0 表示读盘
```

## 2. struct buf 结构体需包含的最小字段集（参考 virtio_disk.c 实际访问）

| 字段 | 数据类型 | 语义说明 |
|---|---|---|
| `data[BSIZE]` | `uchar[BSIZE]` | 存放磁盘块数据的 DMA 缓冲区（驱动直接将其物理地址填入描述符） |
| `blockno` | `uint` | 扇区编号换算：设备扇区 = blockno × (BSIZE/512) |
| `disk` | `int` | 传输状态标志位：驱动发起传输时置 1，中断处理完成时置 0；**休眠等待通道 = &b->disk** |
| `valid` | `int`（可选） | 供缓存层内部使用，驱动不直接访问 |

字段命名可根据个人设计调整——驱动统一通过 `b->xxx` 访问，学生可通过宏定义、重命名或包装结构进行对齐，无需重写驱动。

## 3. 驱动对内核调用上下文的假设与要求

1. `virtio_disk_rw` 内部会在 `b->disk == 1` 时调用 **sleep** 进入等待 —— 因此调用者必须处于**进程上下文**，且在调用时不得持有自旋锁（禁止在中断上下文中调用磁盘读写接口）；
2. 磁盘完成中断在中断处理例程中对 `&b->disk` 执行 **wakeup** 唤醒 —— 在 lab4 中实现的 sleep/wakeup 机制必须支持在中断上下文中安全触发唤醒；
3. 块大小 BSIZE 与底层扇区的换算固定为 `BSIZE / 512` —— 随意修改 BSIZE 会破坏硬件 DMA 对齐与扇区寻址，lab6 规范要求统一保持标准 BSIZE。

## 4. 压力测试规范（教师验收与评测）

上述 3 项规范为驱动与内核缓存层的唯一耦合接口；极限压力测试将重点验证：高并发调用 virtio_disk_rw 不发生描述符耗尽丢失、设备中断能够可靠触发进程唤醒。其余关于缓存替换策略与 WAL 日志机制的实现细节，均属于学生的自主设计空间。
