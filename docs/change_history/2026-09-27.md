# 2026-09-27 变更记录

## 完成 Lab 1 启动与串口输出

### 现状

个人内核的五个核心文件只有课程骨架注释，构建时缺少 `_entry`，QEMU 冷启动没有串口输出。Lab 1 要求从这个基线建立启动路径，打印个人 Banner 并验证格式化边界。

### 实施方案

`entry.S` 清理 BSS、配置 4 KB 栈和对齐的异常向量；`start.c` 配置 S 态入口、委托、Bare 地址空间和 PMP。`console.c` 轮询 UART 并按学号周期节流，`printf.c` 处理实验用到的格式，`main.c` 输出 Banner 与可检查的边界自检。跨文件声明集中在新建的 `defs.h`，Makefile 补充头文件重编译依赖，`expect_banner.txt` 固定个人协议的预期首行。实验要求、设计依据和调用路径写入 `labs/lab1/lab1.md`，实际输出由 `labs/lab1/test_lab1.py` 检查。

### 完成与未完成状态

Lab 1 的启动和输出功能完成，根目录与个人内核 README 已更新。个人内核的课程只读支撑文件保持原样。本轮以 `lab1-start` 标记起点，验收提交以 `lab1-submit` 标记。链接器对预置链接脚本生成的单一 RWX 加载段仍提示权限警告；这项结构性提示及 `-z separate-code` 的核查结果记录在 Lab 文档中，当前 QEMU 功能验收正常。

### 验证

干净编译消除了原有 `_entry` 缺失警告，ELF 入口为 `0x80000000`。`check_expect.py` 校验协议 0 首行，独立 QEMU 测试核对数字边界、空字符串与 512 字符输出。课程评测返回 Banner 匹配、两次冷启动一致和异常日志清洁，`RESULT: 3/3`。测试后清理构建产物，保留源码与记录。
